## 4. 开新变更单的模板

```
# AM-0xx · 一句话标题
1. 背景/实测依据（可复现，脚本名）
2. 变更内容（契约面 / 代码面 分开列）
3. 影响面（哪些包、哪些文件 —— 不得与他人文件重叠）
4. 逐包动作清单 + 验收判据
5. 应用记录（每包应用后追加：时间 + 验证结果）
```

- 只影响**一个包**的内部修改 → 不开变更单，写进该包文档即可。
- 状态符号：⬜ 未决 → 🔶 部分应用 → ✅ 全部应用并验证 → 归档（总表留一行）。

- 硬约束（实测）：`file://` 下 `fetch` / `XHR` / `decodeAudioData` 全被拦 → 音效只能走
  `<audio>` 元素池（同 `slapPool`）。`SLAP_DELAY=4000` 的存在证明「启动瞬间多元素并发会把 BGM 挤死」。

    **BGM(0) → slap(4.0 s) → tick(5.2 s) → bird(6.5 s)** 错峰。

**5 · 修掉的一处既有缺陷（预存，本包把它变成必现）**
`tryFileBgm()` 建图后**从未刷新元素音量**：`bgmMode` 要等起播后 ~0.9 s 才置位，而那时
`currentTime` 已越过 `LOOP_FADE_IN` → 循环包络恒为 1、提前 return → `elVolApply()` 一次都不执行，
元素停在 `el.volume = P.bgmVolume`（0.60）**比母带目标响 0.94 dB**，直到首次 duck 或第一圈回卷才纠正。
修法：建图分支之后补一行 `elVolApply()`。**本包自造的 bug 一并记档**：`bgmSwitching = true`
原先只在 `setBgmTrack()` 置一次，第二段淡入没人推进 → 包络恒 0；已挪进 `switchRamp()`（两段式）。
