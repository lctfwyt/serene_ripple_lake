## 2. 实测依据（全部可复现）

> ⚠️ **本机没有 `ffmpeg` / `ffprobe`，Python 也没有任何音频库**
> （`pip install numpy soundfile pyloudnorm` 在镜像**同一字节处连续两次** `IncompleteRead` 截断）。
> → 改用**无头 Chrome 内解码 + 页面内计算**：`fetch` → `decodeAudioData` → 自实现
> **ITU-R BS.1770-4**（K 加权解析系数：高架 1681.97 Hz/G=3.9998/Q=0.7072 + RLB 38.135 Hz/Q=0.5003；
> 400 ms 块 / 75 % 重叠；−70 LUFS 绝对门 + −10 LU 相对门）与循环接缝包络。
> **零外部依赖，而且量的就是浏览器实际解码出来的 PCM。**

### 2.1 资产响度

| 资产 | 时长 | 采样率/声道 | 峰值 | **集成响度（BS.1770-4）** |
|---|---|---|---|---|
| `bgm-stillwater.mp3` | **146.832 s** | 48 kHz / 2ch | 0.9514 | **−15.06 LUFS** |
| `slap1.wav` | 1.45 s | — | **0.62** | −20.27 LUFS |
| `slap2.wav` | 1.45 s | — | **0.62** | **−21.12 LUFS** |
| `slap3.wav` | 1.45 s | — | **0.62** | **−18.63 LUFS** |
| `slap4.wav` | 1.45 s | — | **0.62** | −20.18 LUFS |

两个关键判读：

1. **BGM 偏响 +0.94 LU** → `BGM_TRIM = 10^(−0.94/20) = 0.8974` → **−16.00 LUFS**。
2. 🔴 **拍击「峰值统一 ≠ 响度统一」**：4 段峰值都是 0.62，但集成响度跨 **2.49 LU**
   （`slap3` 比 `slap2` 响 2.5 dB）→ 点击会被听成「忽大忽小」。
   → `SLAP_LUFS_TRIM = [1.0256, 1.1312, 0.8491, 1.0151]`（归一到四段均值 −20.05 LUFS）；
   **平均增益 1.0053（≈0 dB）→ 平均电平不变**；最大有效峰值 `0.62 × 1.1312 = 0.701 ≪ 1.0`（不削波）。

### 2.2 循环接缝 —— 这里有两个坑，不是一个

10 ms 窗口包络（dB）：

```
首 40×10ms: [-120, -139.7, -52.4, -46.3, -48.7, -49.7, -51.6, -55.6, -54.8, -52.7,
              -24.4, -13.7, -15.9, -18.1, -21.8, -23.5, ...]
尾 40×10ms: [-25.4, -26.8, ..., -27.5, -29.3, -32.7, -48.4]
首个 |x|>0.05 的样本：idx=5186 → t = 0.108 s
```

| 项 | 实测 | 判读 |
|---|---|---|
| **曲首** | `0~20 ms` **绝对零**（−120 / −139 dB）· `20~100 ms` 仅 −46~−55 dB（量化噪声底）· **0.108 s 才有第一个有效样本** | 🔴 **曲首 ~100 ms 数字静音** |
| **曲尾** | 一直有声（−25~−29 dB），最后 10 ms 落到 −48.4 dB | 尾端自带 ~10 ms 收尾 |
| 轨内一步跳变 p99.9 | 0.02469（窗内最大 0.05814） | 用于「接缝跳变是否自然」的参照 |
| 接缝硬切一步跳变 | **0.05101** | ≤ 窗内自然最大跳变 → **首尾波形本就接近连续** |

**按「接缝前后 50 ms 能量差」口径**：`head50 = −50.68 dB`（落在数字静音上）vs `tail50 = −29.87 dB`
→ **20.81 dB** —— 这不是「咔」，而是每 146.8 s 一次 **~100 ms 的静音塌陷**（一次"呼吸"）。

🔴 **第二个坑（第一次修法没修掉、验收挡出来的）**：
元素的 `duration` 是浏览器**按码率估算**的，本资产在 `file://` 下报 **147.164 s**，而音频数据只到 **146.832 s**。

| 环境 | 元素 `duration` | `buffered` 末端 | 解码真实长度 |
|---|---|---|---|
| `http`（带 Range） | **146.832** ✅ 真值 | 144.878 → 之后到尾部 | 146.832 |
| `file://`（**交付形态**） | **147.164** 🔴 估算值 | **147.164** 🔴 **也是估算值** | 146.832 |

→ 出点若取 `duration − 0.03 = 147.134 s`，**正好落进末尾那 0.332 s 无数据区** → 每圈塌一次静音。
→ 而且 **`buffered` 封顶这条路在 `file://` 下走不通**（buffered 末端同样是 147.164）。
→ 最终解法见 §3 第 11 条：**实测常量 + 守卫**。

**判据口径的说明（重要）**：`90-WAVE4 §3` 第 6 条只写「前后 50 ms 能量差 / 波形连续性」，**未给数值**。
本包按**现象**定阈，依据写清：

1. 「能量差」这一项的**用途是探测一侧是否为数字静音空洞**：这类空洞实测 **≤ −120 dB**
   （曲首 0~20 ms 就是 −120 / −139 dB），而有声区 ≈ −30 dB → 相差 ~90 dB。
   故判据取「两侧 50 ms 均 **> −60 dB**」即可无歧义判定「两侧都是有效音频」（留 30 dB 余量），
   并要求「\|Δ\| **< 10 dB**」—— 空洞情形是 20.81 dB，10 dB 与之差一倍以上。
   残留的 **3.28 dB 是乐曲首尾自身的音量差**（不是空洞），且两侧包络已被压到 0，不成其为爆音。
2. 「波形连续性」= 接缝处**输出**是否跳变。包络两端 gain = 0 → 输出跳变恒为 0（构造性质，已验）。
   附加诊断：即便**硬切**（不加淡变），接缝 PCM 一步跳变 0.05101 也 **≤ 窗内自然最大跳变 0.05814**
   —— 说明本资产的首尾在波形上本就接近连续（这也是能量差能这么小的原因）。
   该诊断只对**运行期真实出点**成立（换切点会落在别的波形相位上，实测提前 100 ms 时该值 0.07071），
   故**不进**稳健性判据。

> 📌 本包曾把阈值定成「\|Δ\| ≤ 1.0 dB」，实测 3.28 dB 判负 —— 复盘认定为**判据本身设错**
> （该量是空洞探测器，不是电平匹配器），已按上面的口径重设并在此备案。

## 6. 遗留 / 交还主控

| # | 项 | 说明 |
|---|---|---|
| 1 | **⑥ BGM stems 不做** | 曲目无分轨源料（AM-012 §3.3）。若将来换支持分轨的生成器，可另开单 |
| 2 | `BGM_TRUE_DUR = 146.832` 是**实测常量** | ⚠️ 换 BGM 后需重测（`README.md` 有 `cp assets/audio/bgm-cand1.mp3 …` 的替换说明）。**守卫**（差值 ≥ 1.0 s）会使其自动退回估算式 → **不会静音**，最坏是留尾静音 |

| 4 | `LOOP_FADE_OUT/IN = 40 ms` 的**听感**未经真机试听 | 40 ms 是「避免"咔"」与「凹陷尽量短」的折中。若雨桐觉得每 146.8 s 有一次"呼吸"，可调大到 80~120 ms（元素路台阶会同时变细：40 ms/5 ms = 8 级 → 120 ms/5 ms = 24 级） |

| 6 | `#13` 单帧 argmax 仍是相位噪声 | 归 AM-008 裁决（已降级为诊断读数），非本包范围 |
