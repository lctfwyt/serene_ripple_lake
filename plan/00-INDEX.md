# still_water 工作包索引

> 项目：`D:\projects\still_water` —— Three.js 治愈湖面
> 本目录把开发计划拆成 **5 个工作包（WP）+ 1 份接口契约 + 1 份变更单**，每个 WP 交给**一个独立聊天框**完成。
> 目的：每个聊天的上下文只装它要干的那部分，互不挤占。

---

## 0. 怎么用

**每个新聊天框的开场白格式**（**六份**文件缺一不可）：

```
@plan/00-INDEX.md @plan/01-CONTRACT.md @plan/02-AMENDMENTS.md @plan/03-COLLAB-PROTOCOL.md @plan/04-BOARD.md @plan/20-WP2-water-ripple.md
先读 02-AMENDMENTS.md，应用所有影响本包的未决变更单；再看 04-BOARD.md 有没有指向本包的未处理留言；然后按 WP2 开工。
动手前先复述：你拥有哪些文件、哪些文件不许碰、本包要应用哪几条变更单。
收尾按 03-COLLAB-PROTOCOL.md §7 四步；提交按 §7.1（只 add 自己的文件、禁 -A；并行波次不提交，交主控统一提）。
```

| 文件 | 作用 | 不读会怎样 |
|---|---|---|
| `00-INDEX.md` | 你在整个计划里的位置、依赖谁、别碰谁 | 不知道边界 |
| `01-CONTRACT.md` | **冻结**的接口签名 + **§9 共享常量**（机位/水位/尺寸）+ 文件所有权 + 事件名 + DOM id | **写出对不上的 API，合并时全废** |
| `02-AMENDMENTS.md` | **★ 跨窗口传话的唯一通道**：已发出的包要改什么、影响谁、怎么改 | **别人改过的规格你不知道，白做或冲突** |
| `03-COLLAB-PROTOCOL.md` | 完工后**写哪、写多少**（台账一行 vs 包文档详情） | 把报告怼进 `_STATUS.md` 断表，重演 v1 失控 |
| `04-BOARD.md` | **★ 留言板**：主控 ↔ 分包传话（求助/裁决/提醒，一行 ≤40 字） | 别人问你的、主控裁的你都看不见，各干各的 |
| `<本包>.md` | 本包的目标、步骤、验收判据、交付 | 不知道做到什么算完 |

**每个 WP 文档顶部有一行 `🛑 未应用变更单` 横幅** —— 那就是提醒。应用完删掉横幅。
若本包文档没有横幅，说明当前没有待应用的变更。

**📐 分包窗口的阅读范围**（省上下文）：
- 本文件**只读 §2 依赖图、§5 全局决策、§6 风险、§7 交付纪律、§8 本机注记**；§1/§3/§4 是主控的导航与历史，**可跳过**。
- 归档文件（`98x-*-ARCHIVE-*.md`）**一律不读**——除非主控在留言板/变更单里点名具体章节。
- §5 与 `01-CONTRACT.md §9` 若有出入，**以契约为准**（契约是唯一事实源，本节只是摘要）。

**唯一例外**：WP2 的关键路径较长，若你担心注意力飘移，可以把 WP1 和 WP2 放在同一个聊天框里连续做（见 §3 波次 0+1 合并说明）。

**为什么 WP1 必须单独先做**：它产出所有模块的**空壳 stub**（函数签名齐、函数体为空）。
有了 stub，WP2/3/4 才能在不互相等待的前提下各自填空 —— 这是整个拆分方案能成立的唯一前提。

**为什么会有 WP1b**：WP1 交付后雨桐提了机位变更（AM-001），影响到 4 个包。
**机位是跨 WP 的隐式约定，所以在 01-CONTRACT.md 里被提升为 §9 共享常量** —— 这类改动以后都走变更单，不再散落在正文里。

| Three.js | **r160 UMD**，本地 `vendor/three.min.js` | 实测 `three.min.js` 在 **r161 起返回 404**（UMD 被移除只剩 ESM）。r160 文件 669884 bytes |
| 引入方式 | **经典 `<script>` 标签**，不是 `type="module"` | ES module + importmap 在 `file://` 下被 CORS 挡死 → 无法双击打开；经典脚本可以 |
| 交付形态 | 多文件 | 单文件内联 669KB 压缩 JS 会让编辑器卡顿、栈不可读 |
| 波纹 | **波动方程 FBO ping-pong**，不是"shader 内 N 个解析涟漪" | 后者无法互相干涉、无法自然衰减 —— 而"波纹干涉"正是治愈感核心 |
| 划水声 | **程序化 WebAudio 合成** | ① 本机 MiniMax 脚本无 SFX 接口；② 真实录音做不到与拖动速度连续耦合 |
| BGM | **MiniMax 文生音乐**（`music-2.5+` `--instrumental`） | 用户已选；需 `MINIMAX_API_KEY` |
| 音频加载 | `<audio>` 元素 + `createMediaElementSource` | `file://` 下 `fetch`/`decodeAudioData` 被挡，媒体元素可以 |
| 字体 | 中文走系统字体栈 | `@font-face` 从 `file://` 加载有 CORS 风险；中文 web font 动辄 3–8MB |
| 随机数 | 唯一随机源 `mulberry32(SW.P.seed)` | 渲染路径上禁止出现 `Math.random()`，否则无法复现断言 |
| **机位** | **`fov=34` · 俯角 `25°` · 相机在水面之上 4.35** | **AM-001**：雨桐要求「更俯视、网页全是湖水、看不到地平线以上」。俯角**必须 > 17°（= fov/2）** 才能把地平线推出画面。详见 `01-CONTRACT.md §9` |
| **地平线** | **不可见（硬约束）** | 同上。**旧判据「地平线落在 0.42–0.50」已作废** —— 那条与俯角要求互斥 |
| **天空** | 网格保留，但**不承担画面表达** | 看不到天空后，四态差异落在**水面 + 雾色 + 光照**上；`skyTop/skyBottom/starAlpha` 保留字段但无贡献 |
| **反光路径** | **GGX specular + 两层法线**（大波纹 FBO + 高频细节） | **AM-002 采纳**。参考图的核心视觉，也是补上「天空被移出画面」后的夜景表达缺口。**只用一层法线做不出破碎柱** |
| **光源方位** | **落在 `min(22°, hHalf − 6°)` 以内**（`hHalf` = 水平半视角，随窗口宽高比变） | **AM-003 改写 AM-002 的 `±75°`**。原来写死 ±75° 是错的：反光柱的方位安全区**就等于 `hHalf`**。实测：**16:9 画布（1280×720）28.53°** · 1254×720 → 28.03° · 16:10 → 25.66° · 方形 → 16.40° · **竖屏只有 12.73°**。所以必须按宽高比夹取（`AM-003 §3`；`hHalf` 口径见 **AM-007 §1.1**） |
| **光源仰角** | **恒为正**；晨/昏/夜落在 **[22°, 30°]**，硬上限 **32°**；正午 ≥ 33°（建议 64°） | **AM-003**。实测 `shape`：22° → 7.63 · 30° → 1.81 · 34° → 1.01 · 38° → 0.63 · 46° → 0.26。**`AM-001 §4.3-5`「夜间 `sunElev < 0` → 强度归零」作废** —— 夜间要的是**月亮**（正仰角、低强度、冷色） |
