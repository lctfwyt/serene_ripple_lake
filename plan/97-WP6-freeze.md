# WP6 —— 参数固化流程（可复用模板）

> **这不是一次性任务包，是一份流程模板。**
> 每次雨桐在 `?debug=1` 滑杆上调出满意的组合后，**新开一个聊天框**，把本文 §1 的输入段填好发进去，
> 执行包按 §3 的八步把数值固化进代码。
> 变更单：**AM-013**（首次）；后续每次固化续开或在同一张单下追加。

---

## §1 输入（开包时由雨桐填写）

```
本次要固化的参数（从 ?debug=1 面板抄）：
  bloomStrength  = ____
  bloomThreshold = ____

  vignetteAmp    = ____
```

---

## §2 🔴 红线：哪些参数会碰到断言

| 参数 | 影响的断言 | 说明 |
|---|---|---|
| `bloomThreshold` / `bloomStrength` / `bloomRadius` | **#13**（反光柱 peak/median ≥ **1.9**）、#6、#8 | 阈值调低 → 更多中间调进 bloom → peak/median 比值会变 |
| `glitterDetail` / `glitterRough` / `glitterJitter` | **#13** | 直接改碎光强度，最敏感 |
| `vignetteAmp` / `grainAmp` | #13（轻微） | 实测 grain 基本不碰判据；vignette 压暗边缘有轻微影响 |

**铁律**：
1. **断言阈值一个都不许改。** 红了就报主控重标（`#13` 现在是 1.9，实测带 2.12~2.15，地板留了 10% 余量）。
2. 改完**必须**跑 `npm run assert`，把 #13 的前后读数写进报告。
3. 别顺手改别的东西——固化包只做"把数值写进代码 + 验证"。

---

## §3 八步流程

| 步 | 动作 | 命令 / 位置 |
|---|---|---|
| 1 | 核对输入值在合理区间（对照滑杆 min/max） | `src/90-debug.js` 的 `defs` 数组 |
| 2 | 改 `src/00-config.js` | post 段（约 50-51 行）、glitter 段（约 72 行） |
| 3 | 契约 §6 参数段同步（约 326-330 行）+ §10 变更记录一行 | `plan/01-CONTRACT.md` |
| 4 | 重建 dist | `npm run build` |
| 5 | 重落 dist 基线并核对 | `npm run pw:dist:snapshot` → `npm run pw:dist` |
| 6 | 🔴 跑断言，记录 #13 前后读数 | `npm run assert` |
| 7 | 若改了 UI 相关参数才跑全链（纯音频/渲染参数可省） | `npm run pw` |
| 8 | `_STATUS.md` 追加一行；`README.md` 若涉及默认行为变化则同步；提交 | — |

**两入口纪律**：`file://` 双击与 `dist/` 是两条并行的验收线，`src/` 一改就必须重建 dist，否则 dist 基线检查（`pw:dist`）会红。

```

改动文件：src/00-config.js（第 50 行）、plan/01-CONTRACT.md（§6 / §10）
dist：    npm run build → 756,xxx B（基线已重落并核对）
断言：    15/15 通过 · #13 读数 2.13 → 2.20（阈值 1.9，余量 +15%）
其他：    pw 全链 14 passed（未改 UI，基线无需重录）
提交：    xxxxxxx
```

**若 #13 读数逼近 1.9（余量 < 10%）**：照常提交，但在留言板主控箱挂一条，由主控决定是否重标。

## §5 一个提醒给执行包

滑杆的数值**只改运行时，不落盘**（这是特意设计的，方便反复试）。
所以"调满意了"这件事**必须由雨桐把数值抄下来**——你没法从仓库里读出来。
输入段缺哪项就问，不要猜、不要用"审美上差不多"的默认值。
