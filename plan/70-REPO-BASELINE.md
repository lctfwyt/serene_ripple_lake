## 1. 开工前的仓库现状（三个与预期不符的事实）

| # | 事实 | 影响 |
|---|---|---|
| **1** | 仓库是**全新的**：分支 `main`，**零提交** | 基线怎么定完全自由，没有历史包袱 |
| **2** | 但 37 个文件**已经被 `git add` 进暂存区**（`8938 insertions`），且**没有 `.gitignore`** | ⚠️ **`.gitignore` 此刻加已经拦不住已暂存的文件** —— 必须显式 `git rm --cached`。这是最容易被忽略的一步 |
| **3** | 项目里**没有 `.workbuddy/`**，且密钥全在仓库外 | ✅ 无泄漏风险（详见 §6） |

另有两条影响本次决策的环境事实：

- **`core.autocrlf = true`**（Windows 默认），而 `vendor/three.min.js` 是**纯 LF、恰好 669884 字节**。
  → 必须把它声明为二进制，否则某次 checkout 会把它转成 CRLF、字节数漂成 ~677 KB，
  契约里「硬锁 r160 = 669884 B」的记录随之失效。**这是 `.gitattributes` 存在的首要理由。**
- **无远端**。纯本地仓库 ← 这一点让 §2 里「不可再生的资产」格外重要：
  没有远端就没有第二份拷贝，**入库 = 唯一的版本化保全**。

## 3. 本次新增的三个版本控制文件

| 文件 | 作用 |
|---|---|
| `.gitignore` | 11 个分类，含**为 Tier 1/2 预留**的条目（见 §4） |
| `.gitattributes` | 二进制声明 + **保护 `vendor/three.min.js` 的字节锁** + `.glsl` 强制 LF（UP1 会用到） |

但一旦 UP1 的打包器把它压掉，就**必须**补一份 `LICENSE.three.txt` —— 已在文档里写明这条触发条件。

## 5. 分发策略：`dist/` 不入库，那交付物怎么给

UP1 之后会同时存在**两个入口**（这是 `60-UPGRADE-ROADMAP.md §8` 定的双轨）：

| 入口 | 形态 | 是否入库 |
|---|---|---|
| `index.html`（13 个 `<script>`） | 免构建，`file://` 双击即开 | ✅ **入库** —— 它是"零安装"这条承诺的实体 |
| `dist/index.html`（singlefile 产物） | 单文件，压缩 + tree-shaking | ❌ 忽略 —— 一条 `npm run build` 即可重建 |

**要发给别人时怎么办**：`npm run build` 后手动拷出，或挂 Release 附件。
**不把 `dist/` 入库的理由**：它每次构建都产生新 diff，而它与源码**一一对应** —— 入库等于把同一份信息存两遍，还让 `git log` 变得不可读。

## 7. 关于 Git LFS：不建议启用

| 判据 | 实况 | 结论 |
|---|---|---|
| 最大单文件 | 3.8 MB（`bgm-cand1.mp3`） | 远低于任何托管方门槛（GitHub 单文件限 100 MB） |
| 仓库总体积 | **10.49 MB**（41 个文件） | LFS 一般从数百 MB 起才有意义 |
| 二进制占比 | 89%（音频 7.4 MB + 截图 2.0 MB） | 占比高，但**绝对值小** |
| 本项目的定位 | 「零安装、双击即开」 | LFS 会给每个 clone 者加一道 `git lfs install` —— **与项目气质相反** |

**裁决：不用 LFS。** 若将来仓库超过 ~100 MB（例如 UP3/UP4 引入 2K 贴图全集），再重估。

## 8. 回退方法

```bash
cd D:/projects/still_water

# 看基线
git log --oneline
git show --stat baseline-pre-tier12

# 全部回退到基线（会丢弃所有升级改动 —— 小心）
git checkout baseline-pre-tier12 -- .

# 只回退某个文件（例如 UP1 把 index.html 改坏了）
git checkout baseline-pre-tier12 -- index.html

# 对比某个文件的差异
git diff baseline-pre-tier12 -- src/30-scene.js
```

**建议的施工节奏**：**每完成一个 UP 包就提交一次**（`feat(UP2): bloom 管线`），
不要攒到最后 —— 本项目每个包都有独立验收判据（`60-UPGRADE-ROADMAP.md §3`），
一次提交对应一次验收，回退粒度才够细。
